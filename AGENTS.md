# Contexto del proyecto

Este repositorio corresponde al curso AI Engineering de Coderhouse 2026.

## Entorno

- Python 3.12
- Git / GitHub
- macOS
- El repositorio contiene ejercicios, pre-entregas y proyecto final.

## Objetivo de aprendizaje

Este repositorio tiene un objetivo educativo.

Priorizar aprendizaje y comprensión sobre generar grandes cantidades de
código automáticamente.

El código debe ser suficientemente claro para que una persona que está
retomando programación y aprendiendo Python pueda comprender las decisiones
tomadas y continuar desarrollándolo.

## Forma de trabajo

- Usar soluciones simples antes que arquitecturas complejas.
- Aplicar KISS y evitar sobreingeniería.
- Trabajar incrementalmente.
- Antes de crear o modificar varios archivos, explicar brevemente qué se
  propone cambiar y por qué.
- No implementar partes futuras del ejercicio salvo que se soliciten.
- No asumir requisitos que no estén presentes en la consigna o en el
  contexto proporcionado.
- Si existe una ambigüedad que afecte una decisión importante, explicarla
  antes de elegir una solución.
- No modificar otras carpetas del curso sin necesidad.
- Respetar la estructura y el código existente antes de proponer cambios.
- Explicar conceptos de Python cuando aparezcan por primera vez.
- Preferir código claro y explícito sobre soluciones compactas difíciles
  de entender.
- No hacer commits ni push salvo pedido explícito.

## Dependencias

- Preferir la biblioteca estándar de Python cuando sea suficiente.
- No agregar librerías nuevas sin explicar primero para qué se necesitan.
- No instalar dependencias sin autorización.

## APIs y costos

- No realizar llamadas reales a APIs pagas salvo pedido explícito.
- Cuando sea posible, usar mocks, stubs o datos simulados durante el
  desarrollo inicial y las pruebas.
- Avisar antes de ejecutar una operación que pueda generar consumo de API.

## Seguridad

- Nunca hardcodear API keys, tokens ni credenciales.
- Usar variables de entorno para secretos.
- `.env` nunca debe versionarse.
- Usar `.env.example` cuando corresponda, sin valores reales.
- No mostrar secretos en logs, outputs o mensajes de error.
